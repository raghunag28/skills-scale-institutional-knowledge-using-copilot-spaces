# OctoAcme Project Management Docs

A central entry point to OctoAcme’s project management guidance.

## Project management processes

OctoAcme uses a customer-first, iterative approach with clear ownership and data-informed decisions. Projects move through initiation, planning, execution, release, and close/retrospective. Teams define outcomes, success measures, stakeholders, and initial risks at initiation, then turn approved work into prioritized and estimated backlogs, milestone plans, and a Definition of Done. During execution, teams track work on a project board, collaborate through small reviewed pull requests, test changes, and monitor risks and dependencies.

The Project Manager coordinates delivery, schedules, risks, dependencies, and communications in partnership with the Product Manager, who owns outcomes and prioritization. Developers implement and test features, QA validates acceptance criteria, and stakeholders provide input and approvals. Regular standups, weekly delivery and PM–Product syncs, demos, and stakeholder updates keep work visible, while clear escalation paths address blockers.

Quality is built into the workflow through automated tests, linting, CI and security scans, appropriate integration and end-to-end testing, and manual QA when needed. Releases require acceptance criteria to be met, passing checks, smoke tests, release notes, and a rollback or mitigation plan. Retrospectives after sprints, releases, milestones, or incidents turn lessons into owned and trackable improvement actions.
